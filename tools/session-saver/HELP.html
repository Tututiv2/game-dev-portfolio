Claude Session Saver

One button parks every open Claude Code session. The same button brings them all back — right folder, right conversation, right name.

Using it

  1. Double-click Session Saver.bat It lists every Claude Code session running right now, with the folder each one is in.
  2. Hit SAVE + CLOSE Writes the list to a layout, then closes them. Untick anything you want left running.
  3. Record / stream / reboot The layout sits on disk in layouts\. It survives a restart.
  4. Open it again and hit REOPEN Every session comes back as a tab in one Windows Terminal window, each already cd'd to its own folder with its conversation loaded.
It will not close the session you launched it from.

If you start the app from inside a Claude Code terminal, that session shows as (this window) and stays unticked. Everything else is fair game.

Layouts

The Layout box is a free-text name, not a fixed list. Type a new name and save to keep separate sets — stream, minecraft, vesper — and switch between them. Leave it on last if you only ever want one.

Where they reopen

Reopen as tabs

All sessions as tabs in a single Windows Terminal window. Best on stream — one window to move, one to close.

Reopen as windows

Each session gets its own separate console window, the way launching claude from Explorer does.

Resume full session as-is

Big conversations get asked, on the way back, "Resuming the full session will consume a substantial portion of your usage limits — resume from a summary?". Leave the checkbox off and they come back waiting on one Enter. Tick it and they load whole, with no question asked.

How it does that safely.

Claude Code has no flag or setting for this — the choice only exists as a prompt. So the app answers it: it looks at each reopened session's screen, and only presses a key if that prompt is actually displayed, then double-checks the highlight landed on the right option before confirming. A session that never asks is never sent a keystroke, so it can't type into your prompt box. If anything looks off, it leaves that one for you.

It costs more of your usage limit.

That prompt exists for a reason — loading a large conversation whole is exactly what it is warning you about. Tick this when you want the full thread back, not by default.

Reopened sessions always come back in colour.

Claude Code honours the NO_COLOR environment variable, and some shells set it — a session launched from one comes back plain white and looks broken without being broken. The launcher strips that (and the child-session markers that would otherwise turn transcript saving off) before starting anything.

If something looks wrong

Run Check.bat. It prints what the app can see and the exact command a reopen would run, and it closes and launches nothing.

  claude.exe   : C:\Users\you\AppData\Local\...\claude.exe
  wt.exe       : C:\Users\you\AppData\Local\Microsoft\WindowsApps\wt.exe
  registry     : C:\Users\you\.claude\sessions

Driving it without the window

For a stream deck or a desktop shortcut, skip the GUI:

CommandDoes
-SaveClose streamSave every live session to layout stream, then close them
-Reopen streamBring layout stream back
-SelfTestReport only. Changes nothing.
powershell -NoProfile -ExecutionPolicy Bypass -File "SessionSaver.ps1" -Reopen stream

How it actually knows

Claude Code keeps a live registry of running sessions at %USERPROFILE%\.claude\sessions\<pid>.json, holding the session id, the working directory and the display name. This app reads that, verifies each pid is genuinely a live claude.exe, and saves it. Reopening is just claude --resume <sessionId> started in the folder it came from. Nothing is scraped out of your transcripts and nothing is guessed.
