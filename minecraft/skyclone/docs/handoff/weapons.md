# weapons — hand-off

Module `com.skyclone.mod.weapons.WeaponsModule`. Data generated by `tools/gen/weapons/gen_weapons.py`
(research/data/items.json + NEU recipes + collections unlocks) merged with the hand-written layer in
`tools/gen/weapons/spec.py` (our names, our descriptions, ability parameters, behaviour traits).
Re-run `python tools/gen/weapons/gen_weapons.py` from the SkyblockClone folder after editing spec.py.

## What works (verified how)

(`plugin/src/test/java/com/skyclone/mod/weapons/WeaponMathTest.java`, run locally against JUnit 5.11:
9/9 pass), a generator cross-check that every ability id in the data has a Java handler (0 missing),
and 7 live self-tests the integrator can run with `/sb selftest weapons`. **Nothing here has been run on
the live server yet** (the brief forbids starting it), so every gameplay claim below is "written and
compiled", not "seen in a client".

**Catacombs requirements are dungeon-only (fixed 2026-10-03 after a playtest).** The reference keeps an
item's Catacombs level in a separate `catacombs_requirements` list that applies **only inside a dungeon
run**; ours had it as plain `catacombs:N`, which the dungeons module enforces everywhere, so the
Wyrmbreath Blade (AOTD) in the Graveyard gave no stats and refused every hit with "Requires Catacombs
Level 12!" (44 weapons: 20 in `items.json`, 24 in `items_fallback.json`). This module now OWNS the
requirement key **`dungeon_catacombs:<lvl>`** (registered in `enable()`): outside a dungeon it always
holds; inside one (`Features.Dungeons.inDungeon`) it delegates to the dungeons module's own
`catacombs:<lvl>`, so that module's ignore-requirements dial still works; with no dungeons module it
always holds. All 44 weapons carry it in the data, and `tools/gen/weapons/gen_weapons.py` emits it for
both `DUNGEON_SKILL` requirements and `catacombs_requirements`. Lore footer reads
"Requires Catacombs Level 12 in dungeons." Dial `weapons.catacombs-requirement` (live, no restart):
`dungeon` (default, reference) / `everywhere` / `none`. The old runtime rewrite to `skill:combat:N`
(`weapons.catacombs-fallback`) is gone. Self-test `weapons.catacombs-dungeon-only` fails if any weapon of
ours carries plain `catacombs:`; unit test `catacombsRequirementOnlyAppliesInsideDungeonsByDefault`.
Items already in inventories keep their old footer until re-rendered (`/sb item refresh all`); the gate
itself reads the def, so it is right immediately.

## What is partial / not built

(Rewritten in wave 5; the old list is worked through in "Wave 5 (2026-10-06)" at the end.)

  vanilla arrow behaviour on 0-damage hits, `setAI(false)` freezes vs core's leash). Live-only surfaces so far: the
  Quiver Arrow in slot 9, Phasewarp, raised souls, the Flaming Sword burn, and (wave 5) the right-click class ability
  (a synthetic `PlayerSwapHandItemsEvent`), the Adaptive Blade healer share (a one-tick Health delta) and the
  per-target Magic Find hook.
- Ghoul Buster needs a calendar event id (dial `weapons.spooky-event-id`, default `spooky_festival`) and spooky
  mobs (`extra.types:["spooky"]` or an id containing "spooky").
- Burning Vengeance / Wraith Drain read "the shield switched" from the attunement of your later hits (see Wave 3);
  if the slayer module's shield gate also scales our follow-up TRUE damage to 1%, Burning Vengeance lands for 1% on a
  T2+ demon. Not seen live (Request 11).
- Raise Souls numbers are TUNE (research has nothing beyond "mana depends on the monsters' power", 1 s cooldown, 2/3
  souls): mana 20 + 4 x level (cap 500), a soul hits once a second for its monster's Damage, 40 vanilla HP, 20 s on the ground.
- Class-ability cooldown cuts (Conjuring: Guided Sheep -5 s; Earthen Blade: Seismic Wave -2 s; Fel Sword: Healing
  Circle +10%, Wish -10 s) are DATA on the item (`extra.dungeonClassBonus`) that the dungeons module has to read in
  `ClassSystem.ability/ultimate` (Request 13): the cooldown lives in its run state, which no API reaches. Conjuring's
  "no stray sheep" is lore only.
- Floor rolls (`tiered_stats`) apply only to items stamped with the reference key `ItemData.extra.item_tier`; the dungeons
  module does not stamp its drops yet (Request 14), so in normal play every dungeon weapon still carries the lowest
  roll. `/sb weapons floor <p> <n>` stamps one by hand. The tier -> floor naming ("Floor 3", "Master 1") is TUNE.
- Fear: Great Spook armour left in the wardrobe (Eerie's "Fearnesy") is not counted (no wardrobe read API).
- Wand of Recall has no reference data: Recall = home teleport, 60s cooldown (TUNE).
- Travel scrolls are not ours any more: hub, combatzones, foraging and mining each register their own
  `*_TRAVEL_SCROLL` items and gate their warps with `<module>:scroll:<id>` requirements.
- Jester-chine base mana 30 is TUNE (reference only states +30 per shot). Mend Flesh charges (4/5/5,
  one per 15s) are TUNE. Cleave "portion" is a 25% dial. Several radii marked `// TUNE` in code.
- Crossbows: no crossbow is in our item list, so nothing uses the Quiver Arrow with one.
- Transmission Tuners / the Phasewarp Merger: the reforges module applies them in its anvil now (its hand-off, Request 10
  answered); `/weapons tune|merge` and the Arsenal button still work.

## Known risks

1. **Bow damage routing is unproven live.** Shortbow arrows rely on our synthetic `EntityShootBowEvent`
   reaching core's MONITOR capture, and on-hit arrow bonuses rely on `Bows.current` being set at LOWEST of
   the vanilla damage event while core routes at HIGH. If a hit shows "base 5" damage in
   `/sb combat debug`, the capture did not happen.
2. **Fallback item ownership**: if slayer/dungeons register an id with a different meaning, their def wins
   (by design) and our recipe for it is not registered; but crafting may still hold a reference recipe.
   `/sb weapons info` shows how many fallbacks were left to their owner.
3. **Freezes use `setAI(false)`** on sky mobs (Frost Breath, Cold Snap, Pounce, Gummed Up, Shadow Dance).
   They are restored after the duration and on disable, but a core feature that toggles AI itself could
   fight it.

## Wave 3 (2026-10-04)

Worked the partial list by player impact. All of it compiles (`bash tools/check.sh weapons`: CHECK OK, 196 files),
16/16 JUnit tests pass, the generator was re-run (116 own items, 31 + 46 fallback, 45 + 42 recipes, 0 unmatched spec
entries). Nothing was run live (the brief forbids starting the server).

1. **Drawn bows shoot from the quiver: the Quiver Arrow** (`QuiverArrow.java`). The storage module routes every
   arrow a player earns or picks up into the quiver once String III is reached, so a Hunter / Prismarine / Ender
   Bow could no longer draw at all in normal play. Now, while you hold a drawn bow with no loose arrows, hotbar
   slot 9 shows your selected arrow and count as a "Quiver Arrow" (the reference's own answer: the SkyBlock Menu
   comes back when you switch item); vanilla draws from it, `Bows.onShoot` never consumes it and takes one real
   arrow out of the quiver instead. The proxy is a `TIPPED_ARROW` with the plain arrow model, which core never
   converts or counts (`contentBearing`), so it can not become a real arrow; it can not be moved, dropped, swapped
