# collections — hand-off

Entry: `com.skyclone.mod.collections.CollectionsModule`. Provides `Features.Collections`; owns the
requirement prefixes `collection` and `collection_discount`; stat provider `collections`.
Data: `plugin/src/main/resources/data/collections/collections.json` (217 KB), generated by
`python tools/gen/collections/gen_collections.py` from `research/data/collections.json` + `items.json` +
NEU items + core's `vanilla_aliases.json` (+ research/02 §3.8 for boss collections). Re-run it to rebuild;
it fails unless it produces 90 collections / 790 tiers AND every threshold matches the research/02 §3.1.1
summary table (currently: 90 compared, 0 mismatches).

## What works (verified how)
- **All 90 resource collections, all 790 tiers** (Farming 20, Mining 25, Combat 11, Foraging 15, Fishing 12,
  Rift 7) with exact thresholds, plus **8 boss collections** (7 dungeon floors + the volcano boss, 50 tiers,
  SkyBlock XP summing to the research's 1,015 task max). Verified: generator cross-check vs research,
  unit tests (7/7 pass, run locally with the JUnit launcher against the shipping JSON), self-tests.
- **Counting**: listens to `SkyEvents.ItemGain` at MONITOR, including sack-absorbed (cancelled) gains,
  only when `source.natural`. Item id -> collection via the collection id itself plus aliases
  (modern Material names from core's alias table, e.g. `COCOA_BEANS` -> `INK_SACK:3`, `OAK_LOG` -> `LOG`;
  red+brown mushrooms -> Mushroom; iron/gold ore and raw ore -> Iron/Gold Ingot; rough gems x1 and
  Pristine-proc'd flawed gems x80 -> Gemstone). Enchanted forms never count. Dial multiplier.
- **Co-op**: totals in profile SHARED data (`collections`), with each member's contribution and last known
  name; the tier comes from the combined total; every online member gets the tier-up box; per-member rewards
  are re-synced on `ProfileReady`, so offline members are paid when they log in.
- **Tier-up**: `CollectionGain` per gain, `CollectionTierUp` per tier crossed, "COLLECTION UNLOCKED <name>" on
  first item, and the genre box `COLLECTION LEVEL UP Wheat VII➜VIII` + REWARDS (multi-tier jumps fold into one
  box, SB XP summed).
- **Rewards actually granted**: SkyBlock XP via `Features.SkyLevel.award(p, "collection:<ID>:<tier>", 4, ...)`
  (idempotent key, every member); lump-sum skill XP (58 tiers, e.g. Wheat IX +25,000 Farming) via `SkillService`
  once per member (only marked paid when a real SkillService exists); **+1 Mining Fortune** stat rewards
  (Umber/Tungsten/Obsidian/Glacite, 17 tiers) via the `collections` StatProvider; **+1 Foraging level cap** x3
  (Mangrove/Spiral/Fig IX) via `SkillService.setCap(base max + bonus)`, never lowered.
- **Reward text**: recipe/forge recipe (item name from the REGISTRY, so the owning module's rename shows;
  unregistered items are hidden unless the dial is on), minion recipes, exp discounts, stat/cap, pet/potion/
  enchanted-book recipes, trades, bag slots, boss reward-chest unlocks, SB XP. It also scans
  `Sky.recipes().all()` for recipes gated `collection:<ID>:<tier>` and lists those too (minion tiers collapse into
  one "Wheat Minion Recipes" line).
- **Menus** (research 08 §11.4 layout): `Collections` (painting overview at 4 with % unlocked / discovered /
  maxed, categories at 20-25 + Boss at 31, Go Back to the SkyBlock Menu at 48 when the menus module is present,
  Crafted Minions at 50) -> `Farming Collections` (inner 7x4 grid; undiscovered = gray dye "Find this item...")
  -> `Wheat Collection` tier road (lime unlocked / yellow next / red locked, stack size = tier, progress bar,
  rewards per tier; co-op contributions; Recipe Book button runs `/recipe <id>`). Every menu has Go Back + Close.
  Compiles; NOT yet clicked by a real client (I may not start the server).
- **Requirement resolver** `collection:<ITEM_ID>:<tier>`: tier as number or Roman; ids containing ':' work
  (`collection:INK_SACK:3:5` = Cocoa Beans V; `collection:INK_SACK:3` = Ink Sac III); accepts aliases
  (`collection:COCOA_BEANS:5`), display names and boss keys (`collection:BONZO:2`, `collection:F1:2`);
  `collection:<ID>` alone = discovered. Describe: `&aWheat Collection V`.
- **Boss collections** count from `MobKill` of mobs flagged `boss` whose id contains the boss token as a whole
  `_` word (`bonzo`/`f1`, `scarf`/`f2`, `professor`/`f3`, `thorn`/`f4`, `livid`/`f5`, `sadan`/`f6`,
  `necron`/`f7`, `kuudra`); master mode (`m1`..`m7`, `master`, `mm`) counts 2 (dial); Kuudra counts by tier word
  (`basic` 1, `hot` 2, `burning` 3, `fiery` 4, `infernal` 5).

## What is partial / not built
- Exp discounts (`collection_discount:<enchant>`) and the Time Pocket Bag (`TIMITE` II) are shown and checkable

  (Redstone slots), alchemy (Potion Bag), fishing (bait bag), storage (Quiver, Small Sack of Sacks), bank (remote
  `/bank` = `collection:EMERALD:6`) and crafting (trades.json) read them; **enchanting still does not use
  `collection_discount:`** and nothing reads `TIMITE` II yet (rift).
- Collection-unlock "Recipe" labels for items nobody registered are hidden (dial `collections.show-unregistered-rewards`).
- Gemstone weights for Fine/Flawless gems from treasure chests are not counted (only rough x1, flawed x80) - TUNE
  (research still has no number; Fine = 6,400 rough by compaction if the owner wants it).
- Profiles are only ever CREATED as Classic by core today (`ProfileStore` inserts mode 'normal'); the per-mode boards
  below work as soon as a profile row says `ironman`/`stranded`/`bingo` (admin SQL or a future `/profile create <mode>`).
- Still not clicked by a real client (this phase may not start the server): the leaderboard icon (left/right click),
  `/collection top`, the Collection Recipes list, the Roman-numerals toggle.

## Commands added (player + admin)
- `/collection [category|item]` (aliases `/collections`, `/coll`) — opens the menu, a category, or a discovered
  collection's tier road. Menu path: SkyBlock Menu -> Collections (the menus module calls `Features.Collections.openMenu`).
- `/sb collection list [category]`
- `/sb collection <player> info [item]`
- `/sb collection <player> <item> add|set|remove|tier <n>` (`1.5k`/`2m` accepted; `tier` sets the total to that
  tier's threshold; `add` behaves exactly like a natural gain: events, boxes, rewards)
- `/sb collection <player> <item> reset`, `/sb collection <player> maxall|resetall|sync`
- `/sb collection <player> open [category|item]` (opens the menu for that player)
- `/sb collection <player> check <requirement key>` (e.g. `collection:WHEAT:4`)
- `/collection top <item> [classic|ironman|stranded|bingo]` (player): a board's top 10 + your position, in chat (your
  profile mode's board by default). Leaderboard icon: left-click = your board in chat, right-click = top 3 of every board.
- `/sb collection lb [info|flush|prune|top <item> [mode]]`: table/dial state, pending rows, snapshot age, split /
  live-mode / prune state; `flush` re-notes every online player and writes now; `prune` removes rows of deleted
  profiles now; `top` prints one board with profile ids and the per-board sizes.

## Known risks
- **Double counting with sacks**: if the sacks module ALSO fires its own ItemGain (e.g. re-gives from a sack with a
  natural source), the same item counts twice. Sack withdrawals must use `LootSource.SACK` (not natural).
- **PICKUP is natural**: if any module routes player-dropped items through `loot.give(..., PICKUP)`, collections
  become tradeable. Use PICKUP only for world-generated drops.
- **Boss heuristic** may miss or double-count once dungeons exists (e.g. a two-phase boss with two `boss` MobDefs
  both matching `f7`). Request 1 removes the guesswork.
- Co-op: contributions are keyed by uuid inside the shared object; a member who leaves keeps their contribution in
  the total (genre behaviour), and `/sb collection <p> remove` takes from the named player first.
- Menus not yet clicked in a live client.
- The prune trusts core's rule that a deleted profile closes EVERY membership (`left_at != 0`). If a future core change
  ever leaves a live profile with no open membership row, its rows would be pruned (they come back on its next
  ProfileReady). Turn `collections.leaderboard-prune` off if that ever happens.
