# auction — hand-off

Module `com.skyclone.mod.auction.AuctionModule` (id `auction`). Provides `Features.Auctions` (`lowestBin`, `open`).
Data: `plugin/src/main/resources/data/auction/{prices,bazaar_ref,agents}.json`, generated by
`py -3 tools/gen/auction/gen_auction_data.py` (decodes the AH sample's gzipped NBT with `tools/gen/auction/nbt.py`;
no player UUIDs, names or lore are copied - only item id, unit price and counts).

## Regression fix (2026-10-06) - "Auction not found" right after a purchase

PLAYTEST wave5 #6 (cosmetic). Root cause: a BIN bought into a roomy inventory is paid, delivered AND settled in
the one click (the Agent side or the seller's auto-collect closes the other half), so `evictIfDone` drops it from
memory; the view then re-read the store BY ID and drew the "not found" barrier under "You purchased ...". Same for
a seller collecting coins / a returned item from the view (`m.redraw()` after the claim).
- `Listing.forView(live, held)` (pure): the view now keeps the `Listing` it was opened on and draws it when the store
  no longer has it AND it is settled. An unsettled copy missing from the store is never trusted (store wins); an id
  that never resolved still shows "Auction not found".
- `Listing.outcomeFor(profile)` -> `BOUGHT / WON / SOLD_COLLECTED / ITEM_RETURNED / NONE`; a settled listing shows an
  emerald receipt at the action slot ("Purchase Complete - you bought this for X, it is in your inventory",
  "Auction Won", "Auction Complete", "Item Collected") instead of an error.
- `AuctionMenus.view(Player, Listing, back)` overload; every re-open after buy / bid / cancel / custom bid uses it.
- Tests: 3 unit tests in `AuctionPureTest` (45/45 auction unit tests green) + live self-test
  `auction.view-after-purchase`. Not clicked in a real client.

## Playtest fix (2026-10-03) - COMMON listings always lost money

Playtest (playtest-newplayer): a Wooden Sword (COMMON, NPC value 1) was capped at 5 coins while the cheapest
duration fee is 20, so every COMMON listing was a guaranteed loss. Root cause: the research rule ("price at most 5x
NPC value", 3.5) was applied to the LIST price, but fees come out of that price. The cap now bounds what the seller
**nets**: `AuctionRules.commonValueCap` = 5x NPC value of the stack (dial `auction.common-cap-mult`, description
updated), and `commonCap(s, rarity, npc, amount, bin, minutes)` = the smallest list price that still nets that after
the listing fee, the duration fee and the claim tax (Wooden Sword: 26 coins BIN 1h, 359 at 24h). Fees are a sink, so
this opens no laundering - a buyer can still move at most 5x NPC value to the seller through junk. `checkPrice` now
takes `bin, minutes` (the cap depends on the terms); new `netIfSold`. Related: the Create screen shows the cap for the
chosen duration and a "You keep if sold" line (red "(a loss)" for any item whose price does not cover its fees); the
auto-filled suggested price and the Price Guide "use suggested price" click are clamped under the cap instead of
filling a price the submit button then refuses (`AuctionHouse.priceCap`). Tests: `AuctionPureTest.commonCap` updated,
new `commonCapNeverForcesALoss` (every NPC value x stack x BIN/auction x duration nets >= the value cap and the cap is
tight); live self-test `auction.fees-match-research` checks every preset. 32/32 unit tests, `check.sh auction` CHECK OK (185 files).

## What works (verified how)

Verified by `bash tools/check.sh auction` (**CHECK OK, 183 files**) and **31 unit tests** (all pass):
`AuctionPureTest` (22: fees, tax, increments, anti-snipe, limits, COMMON cap, durations, words, browser filters/sorts,
tabs, settlement, Agent bands, shipped data, control characters) + `VaultAndGuardsTest` (9: ranked bidding, ties,
raises, dial parsing, time left in the year, lot layout, and the fair-value guards). Run standalone with plain javac +
the JUnit launcher (`$TMPDIR/skyclone/auction/test.sh`), no gradle lock. Plus 9 live self-tests for the integrator.
**NOT run on the live server** (module agents do not start it) - no menu has been clicked by a real client.

- **Escrow, all on the main thread** (the main thread is the lock: two players racing for one BIN are serialised).
  Memory is authoritative; every change is a full-row snapshot queued on the single FIFO DB thread
  (`auction_listings`, `auction_bids`, `auction_pending`, `auction_sales`, `auction_npc_daily`, `auction_log`,
  `auction_vault_lots`, `auction_vault_bids`). Auctions survive restarts (unsettled rows reload at enable; settled rows
  are kept as history for `auction.history-days`).
- **Create Auction**: click an item in your inventory -> it leaves the inventory and sits in the Create slot,
  stored in the DB (survives logout/restart, shown again next time; clicking another item SWAPS). Price via
  `inputNumber`, duration presets 1h/6h/12h/24h/48h with their fees + custom (`3h`, `90m`, `2d`, `1d12h`, 5 min..14 d),
  BIN/Auction toggle, live fee breakdown, Price Guide with one-click "use suggested price", confirm screen. The new
  listing row and the removal of the slot item are ONE transaction. Fee charged first; refused cleanly if short.
- **Rules (research 05 section 3), all dials**: BIN fee 1% / 2% from 10M / 2.5% from 100M; auction fee 5%; duration
  fee table 20/45/100/350/1,200 ... 55,200 (piecewise linear between the research points - TUNE in between);
  claim tax 1% over 1M never below 1M (x the mayor perk's value while `derpy.quad_taxes` is active);
  min raise 2.5% (dial; the old 15% is one `/sb dial set` away); anti-snipe 2 min; BIN grace 20 s; listings 14 +3 per
  extra co-op member, max 35; COMMON items may net at most 5x NPC value (fees added on top of the cap); 1 .. 50B price range. Refuses `no_ah`,
  `soulbound`, `no_trade`, `no_auction` tags, ADMIN rarity, non-sky items (incl. the SkyBlock Menu star).
- **Access**: at the hub Auction House (40 blocks of the Auction Master), or anywhere with requirement `cookie`.
  Ironman = cosmetic-only; Stranded/Bingo refused.
- **Bidding**: Confirm Bid screen; coins leave the purse at once; the previous top bidder is refunded immediately with
  `depositOffline(profileId, ...)` (online or not, to the profile that bid); you cannot bid on your co-op's auction or
  over your own top bid; custom bid amounts; bid history (last 10) in the view.
- **BIN**: confirm screen with purse-after; item delivered at once if there is room, else waits under View Bids.
- **Ending**: a 1 s sweeper marks SOLD/EXPIRED; winners/sellers notified with clickable chat (`/ahview <id>`).
- **Claims are idempotent**: the claimed flag is set and queued BEFORE coins/items are handed over. Claim per listing,
  or Claim All (Manage Auctions / View Bids). Any co-op member can manage and claim the profile's auctions.
  A unique item is never delivered to a player who already holds that uuid (crash-rollback guard, logged).
- **Browser**: six tabs down the left (frame glass recoloured per tab), 24 results per page, search across all tabs
  over name + lore (every word must match; `/ahs <words>`), Sort (Highest/Lowest/Ending Soon/Most Bids/Newest),
  Item Tier filter, BIN filter, right-click any cycle to go backwards, `/ah <player>` = that seller's listings,
  settings remembered per player, live 1 s refresh of timers.
- **Auction View**: item with seller, price/bids/top bidder/time left/your status; Buy / Submit Bid / Bid Amount /
  Bid History / Cancel (only without bids; fee not refunded) / Collect; seller head -> their other auctions.
- **Vault Auction**: see above.
- **Deeper than the reference**:
  - **Auction Agents (NPC market maker)** so the AH is alive with two players: ~90 consignment listings of real,
    registered auction-type items (gear, accessories, pets, tools; never Bazaar goods) priced from the price guide,
    spread across six price bands. Agents also **buy** fairly priced player BINs (<= 90% of fair value) and bid late
    on player auctions (<= 80%), capped at 5M coins per profile per UTC day INCLUDING bids in flight. Loop-proofing:
    fair value is an anchor players cannot write (sales only lower it); unique items an Agent listed carry
    `ItemData.extra.ah_agent_stock` and are never bought back; cheap Agent *bid* auctions are unique-only.
  - **Price Guide** (`/ahprice`, Price Check menu, Create screen, Auction View): lowest BIN here, median of recent
    player-to-player sales here, market reference (lower quartile of the reference AH sample), and **crafting cost**
    walked through the recipe registry with Bazaar prices.
  - Auction Stats page, notification toggles, a tab-list widget (selling / bidding / to collect), login reminders
    (auctions and Vault wins), "How it Works" fee sheet (incl. remote access), anti-scam coin readouts
    (`12,500,000 (12.5M)`).
- **NPCs**: Auction Master (main menu), Agent 1 (browser), Agent 2 (manage or create) at the contract anchors; first
  visit plays a short pitch once per NPC. Vaultkeeper only with anchor `npc.auction_vault`.

## What is partial / not built

- **Never clicked in a real client.** Every menu compiles and the pure logic is unit-tested, but layout polish (lore
  wrapping, which slot feels natural) is unverified in game. The Vault menus are new in this pass.
- **Crash window between economy and auction writes**: coins move through the economy's own transaction and the
  listing through ours; both are queued back-to-back on the same FIFO DB thread, but they are two transactions, so a
  hard crash between them could lose a bid's coins or a fee. Needs a core change (see Requests).
- **Vanilla inventory vs. escrow** (narrowed 2026-10-03): the player file is now written within a tick of every escrow
  move, but it is still a separate write from our row, so a crash inside that millisecond gap can leave a stackable in
  both places (uniques are caught by the uuid guard on take-back / list / deliver, and since wave 5 reported by
  core's dupe scan).
- Not built here: the Dark Auction and the Stonks Auction (mayors owns and built both). The "delist from browse at
  4m45s" quirk is built but OFF (`auction.browse-hide-seconds 0`; research marks it (?)).
- Ironman's copy of the Special lots is a reading of "its own Ironman-only Shen's" (dial `auction.vault.ironman-special`).
- Vault numbers are TUNE: main-track stocks (3/5/3) and minimum bids (10M/1M/5M), Special stock 2 and minimum 60% of
  guide value. The gates are the research's Museum Milestones 10/20 (wave 5), but progression's milestone XP table
  is itself TUNE. The Vault is one auction per SkyBlock year with the close at year end; the research does not give
  the opening/closing dates inside the year.
- The Regalia Room is a menu (ledger + record) unless the hub builds the room; what the reference room contains
  beyond being a secret room is not in the research.
- Duration fees between research points are linear interpolation (TUNE).
- `lowestBin` includes Agent stock (it is real, buyable stock).

## Commands added (player + admin)

Player (category Economy):
- `/ah [player]` (aliases `/auction`, `/auctionhouse`, `/auctions`) - main menu, or that player's listings.
- `/ahs <search>` (`/ahsearch`) - browser filtered by the words.
- `/ahprice` (`/pricecheck`) - price guide for the held item, in chat (works anywhere: it moves nothing).
- `/ahview <id>` - open one auction (what the chat links run).
- `/vaultauction` (`/vah`) - the Vault Auction.
- `/regaliaroom` (`/regalia`) - the Regalia Room (carry Collector's Regalia; also Vault Auction slot 45).
Menu paths: Auction House main menu -> Browse / View Bids / Create-Manage / Vault Auction / Price Check / Stats /
Settings; the hub NPCs; the SkyBlock Menu via `Features.Auctions.open` (menus module, slot 43).

Admin `/sb auction <action>` (all take player NAMES; output is synchronous for RCON):
`stats` · `list [n] [npc|player|ended]` · `info <id>` · `restock [n] [spread]` · `buyers [force]` · `purge-npc` ·
`create <player> <itemId> <price> [bin|auction] [minutes] [amount]` (fresh item, no fee; BIN still has the 20 s grace) ·
`bid <player> <id> [amount]` · `buy <player> <id>` · `end <id>` · `cancel <id>` (refunds the top bidder) ·
`claim <player>` · `open <player> [main|browse|bids|manage|create|stats|price|vault]` · `price <itemId>` · `audit` ·
`sweep` · `slot <player> [return]` · `vault [status|close|roll|claim <player>|bid <player> <lot> [amount]]`.
Ids accept any unique prefix (the 8-char short id shown in `list`; vault lot ids look like `<year>-<10 hex>`).

Quick RCON loop: `sb auction create Alice ASPECT_OF_THE_END 1m auction 3` -> `sb coins Bob give 5m` ->
`sb auction bid Bob <id>` -> `sb auction end <id>` -> `sb auction claim Bob` / `sb auction claim Alice` -> `sb auction audit`.
Vault: `sb auction vault` -> `sb coins Bob give 50m` -> `sb requirement Bob museum_milestone:10` (shows whether Bob passes the
gate; for a quick test set `auction.vault.requirement` to blank - an unknown prefix such as `always` FAILS closed) -> `sb auction vault bid Bob <lot>` -> `sb auction vault close` -> `sb auction vault claim Bob` -> `sb auction vault roll`.

## Known risks

1. **Agent economy is a new faucet/sink** (TUNE throughout): Agent stock removes coins; Agent buyers add up to
   `auction.npc.daily-cap` per profile per day. The wash-trade loop is closed, but crafting an item below its
   market-reference price and dumping it on the Agents is still profitable up to the cap - lower
   `auction.npc.bin-fraction` or the cap, or switch `auction.npc.buyers` off, if that shows up.
2. **`/ah` now needs the Boon Buff away from the hub** (genre default). If the bank module is missing, requirement
   `cookie` is unknown and fails closed, so `/ah` works only at the Auction House; set `auction.anywhere true` to
   restore the old behaviour.
3. **Unclicked UI** (main AH and the new Vault screens): there may be layout/lore issues only a real client shows.
